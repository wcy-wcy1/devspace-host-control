# 自动化、部署修复与双击启动统一版本

日期：2026-11-11。

## 已整合内容

- 自动探测本机与已授权 SSH 服务器、按阶段记录实际证据、中断后继续。旧进度中的桌面记录必须满足新剪贴板/Xorg 检查；新增启动入口阶段也必须完成，不能凭旧“完成”标签跳过。
- 完整 Tailscale JSON/HuJSON 策略发现、计划、备份、校验、ETag 条件保存及读回验证。保留无关设置和确定不涉及配对设备的业务规则，未知冲突停止。结果未知的写入不会自动重试。
- 两个桌面安装器统一调用只读策略 audit，避免旧检查器拒绝已保留的业务规则。Ubuntu 同时补入官方 Claude 签名密钥指纹核对。
- Windows 防火墙的程序级 IPv4/IPv6 拒绝规则、显式启用关闭配置文件前的备份；保留之前部署时认可的授权边界。
- CentOS 原机适配、密钥环 PAM/目录修复、重复 Xorg 参数保留、无副作用预览、备份/并发检查/部分失败回滚和故障分类。
- 默认开启双向文本剪贴板；服务器、新 RDP 文件、自动化进度和启动入口一致。文件/图片、磁盘和设备共享继续关闭。
- 双击 Start-Claude.cmd：启动或复用 Windows 代理，打开远程桌面，在服务器的 XFCE 登录/重连时拉起 Claude。正常 RDP 登录和本机限时授权仍保留，不嵌入密码、不新增 SSH 通路。
- Skill、README、操作/验收/启动说明及 CI 使用统一资源；完整性检查增加必需资源清单，避免再次漏打自动化文件。

## 本次实际验证

| 检查 | 结果 |
| --- | --- |
| Windows Python 3.14 全部离线测试 | 58 项通过，无跳过；一键入口的模拟新启动同时覆盖 PowerShell 7 与 Windows PowerShell 5.1 |
| CentOS Python 3.9 隔离目录 | 52 项通过，6 项 Windows/PowerShell 测试跳过，无失败 |
| 安装器 | 两个 Bash 语法检查、默认文本剪贴板预览通过 |
| PowerShell | 脚本语法检查通过；现有 Windows 代理进程/配置匹配检查通过，没有启动新进程 |
| 服务器启动钩子 | 预览、应用、再次应用通过；桌面用户运行 helper 返回 already_running，没有关闭/重启 Claude |
| 运行配置 | 只读诊断显示 Xorg 参数有效，无已覆盖故障 |
| 原有程序/源码镜像 | 6 个程序哈希/架构验证通过，32 个 Go 源码镜像一致；未改 Go 程序，未重跑 Go 构建/测试 |

Windows 启动测试使用假进程与假代理，不实际控制用户桌面。Linux 隔离测试使用夹具；完整新装、真实双击后的 RDP 新登录/重连画面、Claude 从完全退出状态自动拉起、文件/图片剪贴板拒绝和实际键鼠输入仍待专门现场验收。不能把“already_running”当作冷启动成功。

此次对现有服务器只增加了选择的桌面用户的 Claude autostart 文件、helper 和默认 reconnectwm.sh 启动钩子；没有重装桌面、重启服务或修改线上策略/防火墙。当前本机已有代理未被停止或重新授权。

## 交付与后续使用

完整项目和自包含 Skill 均含上述内容。本机已安装 Skill 也更新为统一版本，更新前保留本地副本。补丁基于 f6880e838801fe6f0b10e7542208e00da5eb0351，随 v0.2.0-beta.1 发布到 GitHub；以远程提交和 Release 校验值为准。

针对当前机器生成的“Claude一键启动”目录与公开项目包分开，里面只保存已有配置的路径、设备连接设置和脚本，不复制私钥/密码或控制网址。保留整个目录；以后双击 Start-Claude.cmd。控制会话过期后，仍需在本机代理控制页开启限时会话。

打包验证包含补丁的基线应用/当前反向检查、ZIP CRC、必需文件以及部署凭据检查。详细使用方法见 skills/devspace-host-control/references/launcher.md；先前安装教训见 docs/deployment-reliability.md。
